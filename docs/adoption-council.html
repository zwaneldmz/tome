The adoption council

Seven experts, one question: would a tech lead champion Tome? Open-source, agent-agnostic coding harness — evaluated as a product a team stakes its credibility on.

moat: governance plane 2× independent 8/10 code reviews 228 tests green gap: trust surface + packaging

Verdict

Tome has a genuinely differentiated position — the governance plane for agent CLIs: per-pane containment, seatbelt sandboxing, a human-gated conductor. That is the story for AI adoption in B2B SaaS, where shadow AI is now the top blocker. But the repo under-sells it: the README leads with window management, there are no releases, no CONTRIBUTING, and macOS-only unsigned builds cap the champion motion. The moat is policy-as-product; the gap is trust surface and packaging.

Method: seven-expert review of the README, THREATMODEL.md, the UX council report, both prior code reviews (pi 8.0/10, Kimi K3), the improvements plan/status, and the flows feature plan. Every seat answered the same framing question from a tech lead's chair: "My engineers already have Claude Code / Cursor / Copilot — why would I champion this, and what would make me walk away?"

E1

AI Adoption Strategist — B2B SaaS

thesis 🟢 execution 🟠

Every B2B SaaS org has the same 2026 problem: engineers adopted agent CLIs bottoms-up, security found out later, and now there's a spreadsheet of un-audited API keys. Tome's containment is the only shipping answer to "how do I let my team run Claude Code without it being able to curl my source anywhere on the internet."

  • 🟢The wedge is governance, not productivity. "Agents, terminals, editors and chat in one grid" is a Cursor-adjacent pitch and loses. "Run any agent CLI behind a per-pane egress allowlist enforced by the macOS seatbelt, with a second factor to open the pipe" has no competitor. Lead with it.
  • 🟢Agent-agnostic is an adoption superpower. Claude Code, opencode, pi light up on PATH with no config — Tome rides every model wave instead of betting on one. The tool survives the next model switch.
  • 🟠The buyer and the user are different people. The champion is an IC; the approver is the tech lead; the blocker is security. The README speaks only to the champion. THREATMODEL.md is excellent but reads like maintainer notes — ship an evaluation-facing SECURITY.md.
  • 🟠No audit trail. Governance buyers ask "what did the agent do?" The blocked-host flash vanishes in 4 s. A persistent, exportable event log — conductor tool calls, unlocks, blocked egress — turns the containment from a feature into evidence.
  • 🟡Flows are the team story. A committed .flow.json is a code-reviewable multi-agent pipeline — the artifact a tech lead puts in a design doc. It's buried mid-README; it belongs in the hero.

E3

Security Engineer — the approver

core 🟢 surface 🟠

Reviewed THREATMODEL.md against both prior code reviews. The strongest part of the project.

  • 🟢The load-bearing invariants are correct: proxy-widens-never-sandbox, lock-gate wrapping ipcMain.handle (fail-closed by construction), vetted pane kinds, the conductor auto-run guard in main with control-char stripping, second-factor pane unlock. Two independent reviewers at 8/10 is a marketable fact.
  • 🟢The confused-deputy loop is named and capped. Scrollback→model→tool-call is the exact attack security teams worry about; a written, bounded answer (ANSI-stripped scrollback, 8-turn cap, human-gated submit) puts Tome ahead of tools that haven't thought about it.
  • 🔴Unsigned builds kill the enterprise motion. identity: null means Gatekeeper blocks the app; no tech lead can hand an unsigned binary to their security team. Signing + notarization is table stakes. Until then, document the xattr workaround — silence reads as naivety.
  • 🟠TOME_SHOT auth bypass is gated on !app.isPackaged per WS2 — keep it verifiable in CI so it can't regress into a packaged build.
  • 🟠Supply-chain provenance: the SheetJS CDN pin is well documented (§7); add CI-built release artifacts so "the binary matches the repo" is checkable.
  • 🟡TOTP at rest: confirm safeStorage encryption shipped (WS2) — it's a checklist line item in every security review.

E5

Open-Source Strategy

🔴
  • 🟢MIT license — right call for bottoms-up dev-tool adoption. No hesitation.
  • 🔴"private": true while calling it open source — trivial fix, but it signals the repo isn't ready. Same for the missing pieces: no CONTRIBUTING, no issue templates, no roadmap. A tech lead evaluating dependence on a solo-maintainer project judges bus factor by exactly these.
  • 🟠Distribution is the open-source product. A Homebrew cask is the install path this audience trusts — and it forces the signing/notarization fix (E3), killing two findings with one pipeline.
  • 🟠The moat is policy, and policy wants to be data. If the allowlist becomes committable (.tome/egress.json) with org presets shared on GitHub, Tome gains a network effect no pane feature can produce: teams publishing their policies. The engine stays MIT; hosted policy distribution is the eventual honest business.
  • 🟡Community fuel: a tome-flows examples repo demonstrates the conductor story better than any screencast.
  • 🟡Release cadence: even monthly tags signal life. The git history shows intense development; the public surface shows none of it.

Developer Relations
